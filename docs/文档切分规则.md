# KB-RAG 文档切分规则

- 状态：与当前实现同步（2026-10-26）
- 适用代码：`internal/ingest/chunker`
- 相关文档：[设计文档](superpowers/specs/2026-10-23-KB-RAG-design.md) · [人工评测](eval/questions.md)

## 1. 目的与边界

`chunk` 是 KB-RAG 的检索单元。每份文档被切成若干片段，每个片段单独嵌入、写入一条 `chunks` 记录，并单独参与 top-k 检索；生成答案时再按编号拼进上下文。

切分层的职责：

- 输入：`loader.Document{Blocks []Block}`；
- 输出：`[]Chunk{Seq, Heading, Text}`；
- 负责：标题边界、标题路径、段落打包、超长段落拆分、表格拆分、碎片过滤；
- 不负责：文档解析、嵌入、存储、检索排序。

## 2. 数据模型

```go
type Block struct {
    Level int    // 0=正文段落；1-6=标题层级
    Text  string
}

type Chunk struct {
    Seq     int
    Heading string // 例如 "人事制度 > 休假 > 年假"
    Text    string
}
```

`Document.Blocks` 按文档顺序排列。Markdown/DOCX 的标题由 Loader 解析成 `Level>0`；正文为 `Level=0`。PDF 没有真实标题，Loader 会把每页插入为 `第 N 页` 的一级标题。

## 3. 处理流程

```text
Document{Blocks}
  → 按标题维护标题栈和当前正文缓冲区
  → 普通段落：打包到 size 上限
  → 超长段落：按中文句末标点拆分并重叠
  → Markdown 表格：独立成片，必要时按行拆分并重复表头
  → 过滤 <10 字符碎片
  → []Chunk{Seq, Heading, Text}
```

## 4. 切分规则

### 4.1 标题边界

遇到标题时先冲刷当前缓冲区，保证片段不跨标题；然后按标题层级更新栈。

- 标题本身不产出正文片段；
- 标题下没有正文时不会产生片段；
- 页边界（PDF）也是标题边界。

### 4.2 标题路径

维护标题栈。新标题层级为 `L` 时：

1. 弹出所有 `level >= L` 的旧标题；
2. 压入新标题；
3. 后续片段使用当前栈的 ` > ` 连接结果作为 `Heading`。

无标题文档的 `Heading` 为空；PDF 的路径形如 `第 1 页`。

### 4.3 普通段落打包

同一标题下，正文段落依次加入缓冲区：

- 段落之间用换行连接；
- 加入下一段会超过 `size` 时，先输出当前缓冲区；
- 普通段落打包不使用重叠。

### 4.4 超长段落

单个段落超过 `size` 时：

1. 以 `size` 为窗口；
2. 从窗口后半段向前寻找 `。`、`！`、`？`、`；` 或换行作为切点；
3. 找不到切点就在窗口末尾切；
4. 下一片起点回退 `overlap` 个字符，形成重叠；
5. 每片少于 10 个字符时丢弃。

重叠只用于这种超长段落拆分；普通段落打包和表格都不使用重叠。

### 4.5 Markdown 表格

识别条件：表格块从表头行开始，第二行是分隔行（只包含 `|`、`-`、`:`、空格），后面至少有一行数据。

- 表格作为独立片段，不与前后段落合并；
- 表格总长度超过 `size` 时按行拆分；
- 每个片段重复表头与分隔行；
- 单行即使超过 `size` 也不拆开，保证一行数据完整；
- 表格片段不使用字符重叠，靠重复表头保留上下文；
- 整块必须都是表格；表格与普通文字混在同一个 Block 时会回退到普通段落逻辑。

### 4.6 碎片丢弃

最终片段少于 **10 个字符**时丢弃，用于过滤空行、孤立标点和过短碎片。第一期没有专门识别“导航文本”，只依赖该长度阈值。

### 4.7 序号

`Seq` 在单文档内按输出顺序从 0 递增，用于文档内排序与相邻片段定位。

## 5. 参数

| 参数 | 默认值 | 含义 |
|------|--------|------|
| `chunk.size` | 500 | 片段字符上限（Unicode rune） |
| `chunk.overlap` | 80 | 超长段落相邻片段的重叠字符数 |
| 最小片段 | 10 | 小于该长度的片段丢弃 |

必须满足 `size > overlap > 0`，否则 `Split` 返回空。

`size` 是字符数，不是字节数，也不是 token 数；需要按模型上下文精确控制时，应额外做 token 估算。

## 6. 示例

### 6.1 标题与段落

```markdown
# 人事制度

## 休假

年假规定……

## 食堂

食堂开放时间……
```

按默认参数切分：

```text
Chunk 0  Heading: 人事制度 > 休假
Chunk 1  Heading: 人事制度 > 食堂
```

### 6.2 超长段落

一个 1200 字的“年假”段落会按句末标点拆成多个片段，相邻片段重叠约 80 字；不会跨到下一个标题。

### 6.3 表格

```markdown
| # | 动作 | 说明 |
|---|---|---|
| 1 | 发消息总线 | topic=alarm |
| 2 | 推园区平台 | yqpt.SendAlarm |
| 3 | 记活动状态 | activeTracker |
```

表格独立成片。若总长度超过 `size` 被按行拆开，每个片段都以：

```text
| # | 动作 | 说明 |
|---|---|---|
```

开头。

## 7. 各格式差异

| 格式 | 标题来源 | 表格处理 |
|------|----------|----------|
| Markdown | Goldmark 标题层级 | 识别 Markdown 表格，独立成片/重复表头 |
| TXT | 无标题 | 按空行分段，再按长度切分 |
| DOCX | `pStyle` / `outlineLvl` | 由 Loader 拼成普通文本（`单元格 \| 单元格`，行间换行），不进入 Markdown 表格分支 |
| PDF | 每页 `第 N 页` 一级标题 | 逐页提取文本，按段落/长度切分 |

## 8. 限制与运维注意

- Markdown 表格识别只覆盖“整块都是表格”的片段；混排内容按普通段落处理。
- DOCX 表格可能被按普通段落拆开，表头不会自动重复。
- 单行表格过长时片段会超过 `size`，这是为了保证行结构完整。
- 标题边界是硬规则；标题下内容很少时会形成较小片段。
- 修改 `chunk.size` 或切分算法后，已有库不会自动重建：`ingest` 的 SHA-256 跳过只比较文件内容，不包含切分版本。需要删除库或换新库重新 ingest。
- 表格切分解决了片段丢失表头的问题，但不保证相关表格片段一定进入 top-k；检索排序是独立问题。
